# 아날로그 트리거 해제 수정

`controller.mjs`의 `step`에서 0.01 이하의 입력을 0으로 정규화하고, 같은 정규화 값을 기존 속도 계산과 부분 감속 분기에 사용하도록 두 줄을 수정했다. 입력 복사본을 전달하므로 원래 입력과 상태는 변경하지 않는다. 0.01보다 큰 입력은 기존 연속 아날로그 매핑을 유지한다.

원인은 작은 양수의 해제 잔류 입력이 8 m/s² 부분 감속에 들어가고, 양수 목표 속도를 계속 유지하는 것이었다. 수정 후 해제는 기존 36 m/s² 제동으로 12 m/s에서 1/3초에 정지하며 정지 상태를 유지한다. 최고 속도 12 m/s, 반 스로틀에서 0.75초 후 6 m/s, 조향과 경과 시간 처리는 유지했다.

실제로 실행한 검사:

- `node check.mjs`: 수정 전 실패 재현(0.4초 후 약 8.8 m/s), 수정 후 통과.
- `node --check controller.mjs`: 통과.

`check.mjs`는 해제 구간 0~0.01의 1,001개 값에 대해 30/60/144 Hz, 불규칙 시간 간격, 단일 0.4초 업데이트에서 정지와 정지 유지를 검사했다. 경계 바로 위 입력과 여러 아날로그 목표 속도, 반 스로틀 중간/완료 시점, 최대 속도, 기존 조향 계산, 동결 객체 불변성, 추가 상태 필드 보존, 0/음수 시간, 잔류 입력 변화, 정지 후 재가속, 입력 범위 제한도 확인했다.

제공된 bettermakegame 스킬과 입력·이동 참고 지침을 적용했다. 이 검증은 합성 모델의 수치 동작 검사이며 실제 장치, 실제 게임 통합, 체감 반응성은 검증하지 않았다. 연속 입력 구간 전체를 실행으로 열거한 것은 아니며, 해당 구간 전체의 처리는 `<= 0.01` 조건으로 보장한다.
