# 수정 결과

`jump.mjs`의 두 조건만 수정했다. 버퍼 만료를 `>= bufferMs`에서 `> bufferMs`로 바꿔 설정값 경계를 포함하고, 모든 `modal` 이벤트에서 `pending`을 비워 열기·닫기 이후 오래된 점프가 실행되지 않게 했다. 기존 `down` 상태를 유지하므로 모달 안에서 누른 입력은 닫은 뒤에도 해제와 새로운 누르기가 필요하다.

기본 버퍼 80ms, 낭떠러지 이탈 유예 100ms 및 사용자 지정값, 공개 `JumpInput`·`replay` 인터페이스와 다른 이동 규칙은 유지했다. 제공된 bettermakegame 스킬과 control-techniques 참조를 적용했으며, 입력 해석 수정 외 효과나 의존성은 추가하지 않았다.

## 실제 실행한 검사

작업 디렉터리는 지정된 J01-skill 세션 폴더였으며 Node v22.18.0을 사용했다.

- 수정 전 `node check.mjs`: 80ms 경계 착지에서 예상 `[280]`, 실제 `[]`로 실패하여 입력 유실을 재현했다.
- 수정 후 동일 명령: `45 checks passed`.
- `node --check jump.mjs`: 종료 코드 0으로 통과했다.

직접 작성한 `check.mjs`는 기본값·사용자 지정값·0ms 설정에서 버퍼와 유예의 경계 전/정확한 경계/경계 후를 검사했다. 모달 열기·닫기의 대기 입력 취소, 모달 중 누른 키와 기존 누름의 해제 요구, 반복 누름과 점프의 한 번 소비, 사망·부활 초기화, 잘못된 설정값과 타임스탬프 거부 및 동일 시간 허용도 확인했다. 검사 카운트는 코드의 논리 검사 단위이며 일부 단위에 여러 assertion이 포함된다.

## 한계

합성 입력 상태 재생과 문법 검사 결과다. 실제 물리 엔진, 프레임 루프, 키보드·컨트롤러·터치 장치, 체감 응답성은 검증하지 않았다. 창 길이를 늘리거나 게임 감각 개선을 별도로 주장하지 않는다.
