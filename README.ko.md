# Better Make Game

[English](README.md) | [한국어](README.ko.md)

게임의 UI, 조작 피드백, 중요한 사건의 연출 흐름을 개선하는 AI 에이전트 스킬입니다.

게임은 작동하지만 행동과 결과가 잘 전달되지 않을 때 사용합니다. 버튼을 눌러도 반응을 알아보기 어렵거나, 공격이 맞았는지 불분명하거나, 승리 후 보상과 다음 행동이 제대로 안내되지 않는 경우입니다. 스킬은 이런 부분을 확인하고 개선안을 제시하며, 수정 요청을 받으면 해당 범위에서 구현하도록 안내합니다.

목표는 게임에 어울리면서도 플레이어가 이해할 수 있는 완결된 경험입니다. 효과를 늘리거나 비싼 리소스를 쓰도록 요구하지 않습니다.

## 다루는 범위

- 버튼 상태, 터치 반응, 키보드·컨트롤러 포커스, 읽기 쉬운 UI.
- 전투가 있는 게임의 타격감과 피해 전달.
- 보상, 성장, 승리, 실패, 장면 전환.
- 애니메이션·카메라·소리와 지원되는 모바일 진동의 연결.
- 빠른 반복 입력, 애니메이션 중단, 일시정지·복귀, 장면 재진입.
- 색상 외의 신호, 음량 설정, 움직임 감소 설정 등 접근성.

기존 게임 규칙, 판정 타이밍, 보상, 결제, 시각적 개성을 보존합니다. 표현을 다듬는 작업에 새 게임 콘텐츠나 밸런스 변경을 임의로 추가하지 않습니다.

## 진행 방식

1. 요청한 장면, 플랫폼, 작업 범위를 확인합니다. 검토 요청이면 결과를 보고하고, 수정 요청이면 해당 범위에서 변경합니다.
2. 실제 코드와 실행 화면 또는 제공된 자료를 살펴봅니다. 입력부터 행동, 결과, 조작이 다시 가능한 시점까지 흐름을 확인합니다.
3. 기존 UI·애니메이션·오디오 시스템을 우선 활용해 필요한 부분을 작게 수정합니다.
4. 해당 실행 환경에서 결과를 확인하고 반복 조작과 중단 상황도 점검합니다. 직접 확인한 내용과 미검증 내용을 구분합니다.

버튼 하나를 고치기 위해 게임 전체를 감사할 필요는 없습니다. 넓은 범위를 검토할 때는 [gameplay-polish.md](references/gameplay-polish.md)의 상세 기준을 사용합니다.

## 설치

이 저장소를 다운로드하거나 에이전트가 인식하는 스킬 경로에 복제합니다. 폴더 이름은 `bettermakegame`으로 유지하고, `SKILL.md`와 함께 `references/`, `agents/` 폴더도 보관하세요.

관리자의 현재 로컬 환경처럼 `~/.codex/skills`를 사용하는 Orca/Codex 설정에서는 다음과 같이 설치할 수 있습니다.

```sh
git clone https://github.com/Ddrubok/bettermakegame.git ~/.codex/skills/bettermakegame
```

이미 같은 폴더가 있다면 로컬 변경을 백업한 뒤 기존 사본을 갱신하세요. 다른 검색 경로에 중복 설치하지 않는 편이 좋습니다. 필요하면 새 세션을 열거나 호스트의 스킬 목록을 새로고침하세요.

이 스킬은 Markdown 지침으로 구성되어 있으며 API 키, 별도 MCP 연결, 자체 실행 환경을 요구하지 않습니다. 실제 구현에는 에이전트의 일반적인 프로젝트·편집기·실행 도구가 필요합니다. Claude나 Gemini 등 다른 에이전트에도 `SKILL.md`와 참조 문서를 제공할 수 있지만, 자동 설치와 활성화는 호스트에 따라 다릅니다. 이번 공개로 해당 연동의 검증을 보증하지는 않습니다.

## 사용

다음 호출 예시는 Codex용입니다. 다른 호스트에서는 해당 도구의 스킬 활성화 방식을 사용하거나, 스킬 파일을 읽도록 명시적으로 요청하세요.

기존 장면을 검토할 때:

```text
$bettermakegame 전투 장면의 타격감과 보상 연출 흐름을 검토해 주세요.
파일을 수정하지 말고 문제와 근거를 보고해 주세요.
```

특정 조작을 개선할 때:

```text
$bettermakegame 상점 구매 버튼의 피드백을 개선해 주세요.
가격, 구매 승인 로직, 저장되는 보상은 유지해 주세요.
처리 중, 성공, 실패, 빠른 반복 입력 상태를 확인해 주세요.
```

프로젝트 위치, 대상 장면, 플랫폼·입력 방식, 검토 또는 구현 여부를 알려 주세요. 실행 가능한 빌드나 영상이 있으면 타이밍과 소리를 확인하는 데 도움이 됩니다. 스크린샷만으로는 둘 다 검증할 수 없습니다.

## 보고 내용

넓은 범위의 검토에서는 현재 구현, 문제, 근거, 기대 효과, 구현 난이도, 우선순위, 구체적인 검증 조건을 기록합니다. 개선안은 다음 순서로 제시합니다.

1. 영향이 큰 즉시 수정: 불분명한 결과, 사실과 다른 상태 표시, 조작 차단, 마무리 누락.
2. 기존 리소스로 가능한 적은 비용의 개선.
3. 영향이 작거나 기기별 확인이 필요한 후속 개선.

수정을 완료한 경우에는 바뀐 동작, 실제 수행한 확인, 남은 한계를 보고합니다.

## 관련 스킬

| 스킬 | 주요 역할 |
| --- | --- |
| `bettermakegame` | UI 반응, 손맛, 중요한 사건의 시작부터 마무리까지 개선. |
| [kill-game-slop](https://github.com/Ddrubok/kill-game-slop) | 획일적이거나 산만하고, 중복되거나 오해를 주는 게임 표현을 찾아 정리. |

두 스킬은 독립적으로 사용할 수 있습니다. 어느 하나를 먼저 실행할 필요는 없습니다.

## 검증의 한계

빌드 성공이나 코드 검토만으로 애니메이션의 느낌이 좋아졌다고 판단할 수 없습니다. 스크린샷으로는 소리·진동·지연·타이밍을 검증할 수 없습니다. 실행 관찰, 코드에서 확인한 사실, 사용자 보고, 추론을 구분해야 합니다.

이 스킬은 필요한 실행 확인을 안내합니다. 스스로 게임을 실행하는 프로그램이 아니며, 유지율·사용자 선호·상업적 성공을 보장하지 않습니다. 공개를 위한 검사는 패키지 구조와 문서를 대상으로 하며, 여러 호스트에서 실제 게임을 개선하는 행동 평가를 뜻하지 않습니다.
