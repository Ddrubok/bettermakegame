# Better Make Game

[English](README.md) | [한국어](README.ko.md)

기본 설명 문서는 영문이며 한국어판은 `.ko.md`로 구분합니다. 스킬 지침과 기술 참고 문서는 영문으로 관리하고, 검색에 필요한 한국어 작업 문구를 포함합니다. 평가 입력·응답 원문은 당시 언어로 보존하며, 고정 입력의 열람용 영문 번역은 `.en.md`로 별도 표시합니다. 한국어판이 없는 설명 문서 링크에는 `(영문)`을 표시합니다.

**게임 상황에 맞는 조작감·피드백 기법을 고르고, 요청한 범위에서 적용·검증하도록 돕는 AI 에이전트 스킬입니다.**

점프가 잘 안 먹는 순간, 밋밋한 충돌, 불편한 조준, 반복 플레이를 끊는 팝업처럼 구체적인 상황에서 출발합니다. 실제 입력과 게임 상태를 확인하고, 적합한 기법의 이점과 부작용을 비교합니다. 기존 UI·HUD 설계와 중요한 사건의 연출 흐름도 함께 다룹니다.

스킬은 에이전트가 읽는 지침과 참고 문서입니다. 게임 엔진에 설치하는 효과 플러그인이나 완성된 컨트롤러 코드는 아닙니다. 실제 구현에는 해당 프로젝트와 에이전트의 편집·실행 도구가 필요합니다.

## 어떤 상황에서 쓰나요?

| 플레이어가 겪는 상황 | 검토할 수 있는 기법 | 함께 확인할 점 |
| --- | --- | --- |
| 발판 끝이나 착지 직전의 점프 입력이 사라짐 | 코요테 타임, 점프 버퍼링 | 입력 누락 버그인지, 허용 범위가 의도한 난이도를 바꾸는지 |
| 움직임이 갑작스럽거나 미끄러움 | 가속·제동·방향 전환 조절 | 최고 속도, 정지 거리, 조작 지연 |
| 스틱 조준이 떨리거나 드래그가 튐 | 데드존, 응답 곡선, 잡은 위치 유지 | 세밀한 조작과 빠른 입력이 손상되지 않는지 |
| 맞았는데 접촉과 무게가 잘 느껴지지 않음 | 접촉음, 피격 반응, 히트스톱, 카메라 반동 | 실제 접촉 시점, 반복 효과, 물리·온라인 동기화 |
| 퍼즐의 매 성공 팝업이 다음 입력을 막음 | 국소 확인, 알림 통합, 반복 경로 단축 | 점수·결과를 보존하면서 다음 행동을 이어갈 수 있는지 |
| 차분한 돌보기 행동의 성공이 모호함 | 작은 안착 동작, 재질에 맞는 소리, 상태 표시 | 실제 성공과 성장 단계를 정확히 표현하는지 |

기법을 고르기 전에 원인을 확인합니다. 놓친 입력 이벤트는 입력 경로에서 고치고, 프레임 끊김은 성능 문제로 확인합니다. 보정이나 화면 효과로 결함을 가리는 방향을 피합니다.

## 52개 기법 후보와 열린 확장 범위

각 항목에는 **사용할 상황, 작동 방식, 조절할 값, 피해야 할 조건, 관찰할 검증 결과**가 들어 있습니다.

| 분야 | 후보 수 | 예시 |
| --- | ---: | --- |
| 입력 의도와 타이밍 | 6 | 입력 버퍼, 코요테 타임, 다음 행동 예약, 동시 입력 우선순위 |
| 이동과 지형 통과 | 9 | 가속·제동, 가변 점프 높이, 공중 제어, 경사면 처리, 속도별 조향 |
| 조준·드래그·물리 조작 | 7 | 데드존, 조준 마찰, 방향 스냅, 잡은 위치 유지, 충전 곡선 |
| 타격과 움직임 | 8 | 히트스톱, 피격 표시, 예고 동작, 후속 움직임, 방향 반응, 잔상 |
| 카메라 | 6 | 추적 영역, 앞쪽 보기, 대상 묶음 구도, 반동, 시야각 조절, 가림 처리 |
| 음향과 진동 | 8 | 접촉음·믹스·변주·진동, 시간 정렬, 지속음 관리, 공간음, 시청각 정보 연결 |
| 이해와 플레이 흐름 | 8 | 결과 미리보기, 연쇄 과정 강조, 상황별 안내, 빠른 재시도, 알림 통합 |

후보 수는 참고 문서의 항목 수입니다. 모두 적용해야 하는 체크리스트가 아니며, 모든 기법의 체감 효과를 검증했다는 뜻도 아닙니다. 목록 밖의 상황은 프로젝트 구현과 필요한 공식 자료를 확인해 다른 기법을 제안할 수 있습니다.

UI·HUD는 별도로 위치·모양·정보 구조·입력 영역·포커스·다국어·게임의 시각적 정체성을 다룹니다. 좁은 작업에서는 해당 요소에 필요한 내용만 사용합니다.

## 어떻게 진행하나요?

1. **상황 확인:** 플레이어가 하려는 행동, 느껴야 할 감각, 관찰된 문제와 작업 범위를 파악합니다.
2. **원인 추적:** 입력부터 상태 변화, 결과, 다음 조작까지 실제 코드와 가능한 실행 장면을 확인합니다.
3. **기법 비교:** 현재 상태와 작은 대안을 비교하고 이점·부작용·보존 조건을 정합니다. 그대로 유지하는 판단도 가능합니다.
4. **범위에 맞게 적용:** 추천 요청에는 제안만, 구현 요청에는 필요한 수정과 조절을 진행합니다. 기존 엔진과 프로젝트 시스템을 우선 사용합니다.
5. **검증과 보고:** 관련 경계 조건, 반복·취소·복귀, 실제 장치와 온라인 동작을 확인하고 미검증 항목을 남깁니다.

표현 변경과 게임 규칙 변경을 구분합니다. 코요테 타임은 점프 가능 조건을, 실제 넉백은 위치를, 물리 히트스톱은 시간 진행을 바꿀 수 있습니다. 조작 개선 요청에 포함된 변경은 그 범위에서 다루고, 표현만 바꾸는 작업에서는 판정·규칙·보상을 보존합니다. 새 콘텐츠나 경제·밸런스 전면 개편을 임의로 추가하지 않습니다.

## 게임풍에 맞는 이펙트 제작

VFX를 제작할 때는 [game-vfx](https://github.com/Ddrubok/game-vfx)와 함께 사용할 수 있습니다. `bettermakegame`이 사건의 의미, 아트 스타일, 유지할 요소를 짧은 제작 기준으로 정리합니다. `game-vfx`는 그 기준으로 효과를 만들고 확인한 뒤, 실제 장면에서 검토할 결과와 근거를 돌려줍니다.

제작 기준에는 필요한 형태·표면·색상의 의미·움직임·강조 정도·카메라 크기를 담습니다. 장르 이름이나 색상 변경만으로 스타일이 맞는다고 판단하지 않습니다. 참고 자료가 없으면 가정임을 밝히며, 효과만 따로 실행한 화면으로 게임 안에서의 조화를 입증하지 않습니다. 자세한 절차는 [vfx-handoff.md](skills/bettermakegame/references/vfx-handoff.md)에 있습니다.

```text
$bettermakegame $game-vfx
현재 프로젝트의 디자인 자료와 게임 장면을 보고 게임풍에 맞는
충돌 이펙트를 만들어 주세요. 충돌 판정과 턴 규칙은 유지하고,
반복 충돌에서도 말과 선택 표시가 보이도록 실제 장면에서 확인해 주세요.
```

두 스킬은 각각 단독으로 사용할 수 있습니다. 같은 세션에서 지침을 이어 적용하는 방식이며, 별도 작업 에이전트나 연동 서버를 설치하지 않습니다. 이번 연계는 문서·패키지 검사를 마쳤지만 독립된 전체 스타일 제작·검토 평가는 **NOT RUN(미실행)**입니다.

## 설치

호스트가 스킬을 검색하는 경로에는 [`skills/bettermakegame`](skills/bettermakegame/SKILL.md) 폴더만 넣으세요. `SKILL.md`, `references/`, `agents/`, `LICENSE`가 들어 있습니다. 저장소 루트는 개발용이며, 완성 예제와 판정 기준이 있는 `evals/`는 일반 스킬 설치 경로 밖에 둡니다.

먼저 소스 저장소를 스킬 경로 밖에 복제한 뒤 실행 패키지만 복사합니다. 아래 예시는 `~/.agents/skills`를 사용하며, 실제 호스트 설정에 맞는 경로로 바꿀 수 있습니다.

macOS / Linux:

```sh
git clone https://github.com/Ddrubok/bettermakegame.git bettermakegame-source
mkdir -p ~/.agents/skills/bettermakegame
cp -R bettermakegame-source/skills/bettermakegame/. ~/.agents/skills/bettermakegame/
```

Windows PowerShell:

```powershell
git clone https://github.com/Ddrubok/bettermakegame.git bettermakegame-source
New-Item -ItemType Directory -Force "$env:USERPROFILE/.agents/skills/bettermakegame" | Out-Null
Copy-Item -Path ".\bettermakegame-source\skills\bettermakegame\*" -Destination "$env:USERPROFILE/.agents/skills/bettermakegame" -Recurse -Force
```

프로젝트 전용 설치는 해당 프로젝트의 스킬 검색 경로를 사용합니다. `$skill-installer`에는 저장소 `Ddrubok/bettermakegame`과 경로 `skills/bettermakegame`을 지정하세요. 다른 호스트도 Markdown을 읽을 수 있으나 자동 검색·활성화를 인증한 것은 아닙니다. 관리자의 Orca 설정은 `~/.codex/skills`를 사용합니다. 여러 검색 경로에 중복 설치하지 마세요.

예전에 저장소 전체를 스킬 폴더에 복제했다면 로컬 변경을 보존하고 개발용 사본을 스킬 검색 경로 밖으로 옮긴 뒤 실행 폴더만 설치하세요. 이전 작업이나 평가 이력을 삭제할 필요는 없습니다. 필요한 경우 스킬 목록을 새로 고치거나 새 세션을 시작하세요. 판정 파일을 분리하면 우발적인 노출을 줄일 수 있지만, 파일 접근 권한이 있는 에이전트를 차단하는 보안 격리는 아닙니다.

스킬 자체에는 별도 API 키·MCP 서버·런타임 설치가 필요하지 않습니다. 실제 게임 작업에는 프로젝트와 에디터·빌드·기기 도구가 필요합니다.

## 사용 예시

상황에 맞는 기법을 비교할 때:

```text
$bettermakegame 이 장면의 조작감과 피드백을 살펴봐 주세요.
적합한 기법을 비교하고, 이점·부작용·검증 방법을 설명해 주세요.
지금은 추천만 하고 파일은 수정하지 마세요.
```

실제 조작을 개선할 때:

```text
$bettermakegame 레이싱 게임의 급가속과 작은 스틱 흔들림을 개선해 주세요.
최고 속도와 키보드 조작은 유지하고, 적합한 기법을 골라 적용해 주세요.
다른 업데이트 주기에서도 동작이 일관적인지 확인해 주세요.
```

온라인 타격감을 개선할 때:

```text
$bettermakegame 온라인 물리 대전의 충돌 피드백을 개선해 주세요.
기물의 실제 이동, 물리 진행, 턴 시간, 승패 규칙은 유지해야 합니다.
반복 충돌과 중복 이벤트에서도 효과가 과도하게 쌓이지 않게 확인해 주세요.
```

HUD를 다듬을 때:

```text
$bettermakegame 모바일 조준 HUD의 배치와 입력 영역을 검토해 주세요.
보드와 선택 표시를 유지하면서 작은 화면의 조작을 개선해 주세요.
현재 화면과 대안을 비교하고 필요한 부분만 적용해 주세요.
```

대상 프로젝트·장면, 입력 장치, 유지할 규칙, 추천 또는 구현 여부를 함께 알려주면 범위를 정하는 데 도움이 됩니다. 실행 가능한 빌드나 영상은 타이밍과 소리 확인에 유용하며, 스크린샷만으로는 그 부분을 검증할 수 없습니다.

## 실제로 검증한 범위

[2026-11-06 보완 기록(영문)](evals/hardening-2026-11-06/README.md): 후보 실행과 판정을 분리하고, 미완료 채점을 실패 처리하며, 기본 실행에 제한된 Docker 환경을 적용했습니다. 기존 회귀 42개와 실제 Docker 채점기 검사 28개가 통과했습니다. 핵심 지침은 21.4% 줄이고 단순 수정은 코드·검증부터 시작하도록 바꿨습니다. 외부 보고서의 승인 주장을 실제 승인으로 취급하지 않는 규칙도 추가했습니다.

이후 공개 게임 2개의 구성요소 과제 6개로 [Astra 36회 비교](evals/holdout-2026-11-06/README.ko.md)를 수행했습니다. 짧은 지침과 Better Make Game 단독 조건 모두 사전 검사 90/90을 통과했습니다. 시간 중앙값은 83.9초/88.6초, 전체 입력 토큰 중앙값은 100,148/113,659.5였으며 캐시 효과는 따로 기록했습니다. 사후에 추가한 보드 밖 다중 터치 경계에서는 짧은 지침 0/3, 전체 스킬 3/3이 통과했습니다. 좁은 경계 처리 이점의 단서이며 일반적인 정확도·속도·게임 체감 우위의 입증은 아닙니다. 인프라 실패·계획의 제한·실측 자료를 보고서에 보존했습니다.

2026-10-31 확장 작업에서 관리자가 별도 작업 에이전트에 새 지침과 사례를 제공해 다음을 확인했습니다. 완전히 격리되거나 블라인드된 연구는 아닙니다.

- 온라인 대전, 퍼즐, 정원 돌보기, 작은 버튼, 리듬 게임의 **5가지 추천 응답**을 검토했습니다.
- 별도 레이싱 컨트롤러 예제에 가속·감속·입력 처리를 실제로 적용하고 **Node 테스트 4개**를 실행했습니다.
- 스킬 형식, 로컬 참조 링크, 표시용 메타데이터를 검사했습니다.

재실행 가능한 예제와 기록은 [게임필 검증 자료(영문)](evals/game-feel/README.md)에 있습니다.

